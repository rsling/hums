# Milestones

Authoritative, together with `CLAUDE.md` (rules, glossary, layers) and `docs/SCHEMA.md` (document model). Items tagged **[Dn]** are defaults whose status is in `docs/DECISIONS.md`.

Each milestone names a demonstration and its pass criterion. Do not start UI for a later milestone early. Each milestone lives on its own branch; see `CLAUDE.md → Git and done`.

0. **Timing spike and toolchain.** Pin JUCE (9.0.6, for the whole v1 cycle), Catch2, Xcode, CMake, Ninja, ccache, deployment target, all recorded in `TOOLCHAIN.md`. Set up the build shape from `CLAUDE.md → Toolchain` (layer libraries, test executables that don't link the app, a `hums_tests` target), even while most layers are empty: every layer is declared in `src/` with its dependencies, and becomes a library target with its first source — a static library, or an INTERFACE library while it holds only headers (CMake cannot build a library without sources, and a placeholder would be throw-away code). Set up the three build configurations (plain, ASan + UBSan, TSan), `tools/gate.sh` and the sanitizer canaries (`docs/GUARDRAILS.md → Sanitizer builds`); check whether the pinned Xcode's clang ships LeakSanitizer and RealtimeSanitizer [D10] and record the answer in `TOOLCHAIN.md`. Write the `platform/` interfaces and the candidate `platform/mac/` backends; build `tools/miditiming` against the interfaces so one harness compares backends (send-and-measure mode, and a listen mode for milestone 3), measured on a plain Release build. Demo: reports from the software loopback and from one hardware interface [D11] at the three traffic densities, quiet and under tester-produced load (`docs/ARCHITECTURE.md → Timing`). Pass: targets under `docs/ARCHITECTURE.md → Timing` [D1] met or renegotiated with numbers in hand; after touching one render-core source, rebuilding `hums_tests` neither compiles nor links the app; clean-build and incremental test-rebuild times recorded in `TOOLCHAIN.md` as a baseline. Because no render-core source and no app target exist at milestone 0, the incremental time is measured on a `platform/mac/` source as a proxy (decided 20 Nov 2026); milestones 2 and 3 carry the real checks. Decides timer + send path for the engine, i.e. which `platform/mac/` backend the engine gets.
1. **Validated model.** Schema ids, typed wrappers, commands with edit context, Validator, canonical XML writer, atomic save, migrations skeleton, guardrails 1, 2, 3, 5 with negative fixtures. `io/` at this milestone (project file, migrations) includes `model/` only; its build dependency on `render/` is postponed to milestone 2, because `hums_render` has no sources and so no target until then (`src/io/CMakeLists.txt`). Demo: `tools/gate.sh` green in all three configurations, property generator through 10,000 seeds in the plain one. Pass: all guardrails present and known to fail on their fixtures.
2. **Render kernel and interchange.** ClipTemplate, Snapshot, Kernel, NoteTracker, TempoMap (tempo realised as an SMF holds it **[D13]**); guardrail 4 with the full case list; SMF import/export with the policy table; with the first `Smf*` source, `hums_render` is added to `hums_io`'s declared layers (postponed from milestone 1). Demo: import a .mid, export it, show the musical diff is empty and the loss report lists what was dropped. Pass: all goldens green; the incremental `hums_tests` rebuild after touching one render-core source is measured and recorded in `TOOLCHAIN.md`, replacing the milestone 0 proxy.
3. **First musical slice.** Before building the transport, ask Roland Q8 (`docs/DECISIONS.md`: relative or absolute lateness in the listen-mode check). App shell, Routing tab, engine (transport, snapshot handoff, FIFOs, clock out), minimal arrangement display. Demo: open the Berlin fixture or an imported file, play it to hardware, stop, seek, loop, unplug and re-plug the interface, save, quit, reopen. Pass: no stuck notes, timing within targets measured with `miditiming --listen` while the app's GUI is dragged and a save is in progress, recovery file works; touching one render-core source and rebuilding `hums_tests` compiles and links no app code (checked with `cmake --build build-ninja --target hums_tests -v`).
4. **Step sequencer and drum view** (first editor **[D8]**), with enough arrangement to place a clip per track and press play. Demo: build the 5-step bass against 16-step drums from scratch, free-running, knob values recorded into cells. Pass: everything in SCHEMA's example reproducible by hand.
5. **Arrangement and session.** Placements (move, resize, split, crop), slots and scenes, launch rules, refcount gate with badge and make-unique, session recording to take tracks. Demo: jam a scene, record the take, play the take back against the original. Pass: take replays each destination identically.
6. **Piano roll and recording.** EventClip editing, recording from a Performer, quantise and `applyQuantise`, both conversions with loss preview. Demo: record a line, quantise it non-destructively, convert a step clip and edit it.
7. **AutomationLanes and Automation Recorder.** Ownership, exit restoration, lane priority, punch-in/out recording. Demo: record a filter sweep over a looping clip, seek into and out of it, export and verify the CC stream.

## Carried-over issues

Known gaps that are not decisions (those are in `docs/DECISIONS.md`) and are not fixed yet. Each names the milestone at whose start it is picked up; delete an entry in the commit that settles it. Found by the code review of milestone 0 on 20 Nov 2026.

| pick up at | issue |
|---|---|
| milestone 1 | `libs/JUCE_VERSION` is never compared with the submodule's actual tag. A moved submodule would pass the gate with the pin file saying otherwise. A small guardrail script alongside guardrails 1 and 2 would close it. |
| milestone 1 | `tests/guardrails/ToolchainJuceTest.cpp` spells two identifiers as string literals, on purpose and with a comment. Guardrail 1 scans `src/` only, so it is no violation; keep it in mind if the scan is ever widened to `tests/`. |
| milestone 1 | `hums_add_layer` refuses a JUCE-using layer whose first file is a header ("header-only and cannot link JUCE"). `model/Ids.h` alone would trip it; add the first `.cpp` in the same commit, or let a header-only layer link `hums_juce` as INTERFACE. |
| milestone 3 | `MidiScheduler` has no way to ask whether a port has gone; the engine learns it only from refused sends. Decide with the Routing tab how "unassigned" reaches the message thread (JUCE's device-list change, or a query on the interface). |
| milestone 2 | An SMF tempo event has 24 bits, so `TempoMap` **[D13]** cannot hold a tempo below about 3.58 bpm (16 777 215 µs per quarter). Decide with the Validator's `bpm` range whether such a tempo is refused on entry or clamped. |
| milestone 2 | `juce::MidiFile::readFrom` reorders a same-tick note-on / note-off pair of one pitch (`reorderNoteOnsAfterNoteOffs`, unconditional) — the reason `miditiming` reads its reference byte by byte. SMF import promises file order at equal ticks (`docs/RENDERING.md → Equal-tick order`), so the importer cannot use that reader unchanged, and the export must be checked for the same on the way out. |
| milestone 3 | `platform/mac/MachTime` (mach host time ↔ nanoseconds) has no test, and the engine's clock will stand on it. |
| milestone 3 | `miditiming` exits 0 on NOT MET (`targetsMet()` has no caller), so a script cannot use it as a check. Decide the exit code before the milestone 3 pass criterion is run. |
| milestone 3 | Listen mode's recording window starts with the first message on the input. A stray message more than 2 s before playback ends the recording before the playback does (the report then shows drops). Keep the port quiet, or let the window follow the last arrival. |
| milestone 3 | Nothing in `tools/miditiming` is covered by the test suite; its report logic was checked with throw-away harnesses outside the repository. If the milestone 3 pass criterion leans on listen mode, `ListenReport` and `ReferenceFile` deserve tests of their own, which needs a place in the layout (`tests/tools/`?) and Roland's yes. |
