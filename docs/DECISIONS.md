# Decisions

Defaults that were taken by proposal and still need Roland's explicit yes, and open questions. **This file is the only place their status lives.** The text elsewhere tags each default with its id (**[D1]** …); the tag stays when the status changes.

Rules for Claude:

- A `pending` default is binding until Roland answers. Build to it; don't stall on it.
- Never re-ask an item whose status is `confirmed` or `changed`.
- Ask about a `pending` item only when the current task actually depends on it, and then record the answer here in the same session: set the status (`confirmed YYYY-MM-DD` or `changed YYYY-MM-DD: …`). If the answer is `changed`, also edit the tagged text where the item applies.
- An open question that gets answered becomes a decision: move it under *Defaults* with the next free D-number and tag the text it affects.

| D17 | Hums does not optimise for hand-crafted project files. A hand-edited file with an error or an inconsistency is refused on load, never repaired, clamped or defaulted. Added 23 Nov 2026: a `bpm` or `gate` whose exponent has more than three digits is refused as malformed (`1e4294967297` had loaded as 10); Roland on that day: refusing a file for a malformation that is minor or looks harmless is wanted, because it discourages editing project files outside Hums. | D19 | The calls taken while the commands of milestone 1 were written, where the docs had left open how a command behaves (they are in `docs/EDITING.md` and in the headers under `model/commands/`), are confirmed as a set. Among them: every change of a clip passes the refcount gate, its name and colour included; a context that names every reference of a clip still clones under make-unique; a change that changes nothing makes no clone; a new placement starts its clip at offset 0; an overlap is refused and nothing is pushed aside; a placement moves to another track as the same placement; a new track goes to the bottom; removing a track, a lane or a scene leaves the clips in the pool; a scene with an empty name keeps its node; an empty event clip may go on a lane; no command moves a lane or a lane's placement to another track; a new step clip has the default grid and no lane, and a clip may have none; a column is skipped one at a time; changing a knob's CC rewrites nothing recorded (important to Roland). | D20 | A clip made as a copy of another gets the original's name with ` (copy n)` behind it, n counted from 1: the smallest number for which no clip in the pool has that name yet. | D21 | A clip on an AutomationLane is on AutomationLanes only. The commands refuse what would break it, the Validator refuses a project file with one clip on both sides (invariant 9).
