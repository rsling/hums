# Rendering rules (document → MIDI)

Authoritative, together with `CLAUDE.md` (rules, glossary, layers) and `docs/SCHEMA.md` (document model). Items tagged **[Dn]** are defaults whose status is in `docs/DECISIONS.md`.

Implemented once in `src/render/`, used by the engine Snapshot and by SMF export. Tested exhaustively — see `docs/GUARDRAILS.md → 4. Render golden files`.

**Pipeline.** `model → ClipTemplate` (per clip, one loop period, quantisation applied, step grids expanded, chase tables derived; message thread) → `Snapshot` (templates + per-track placement plans, the lanes' placements among them + automation ownership bitsets, one per template: the CC numbers its clip sends + TempoMap) → `Kernel(snapshot, audibleTracks, window)` (loop arithmetic, placement merging, automation merge; engine or export) → `NoteTracker` (same-pitch ownership, pending note-offs per physical destination) → output. `audibleTracks` is the mute/solo result: the engine's live state, or the document's values at export. Export runs Kernel + NoteTracker over `[0, exportLength)` with a one-shot in-memory output. The step from the Kernel's output through the NoteTracker to the output is written once, in `render/Renderer` (decided 25 Nov 2026): at each tick the note-offs that are due, then what the Kernel gives for that tick, a note-on preceded by the off of a note of its pitch that still sounds; where playback or a rendered range ends, the off of every note that still sounds. The engine, SMF export and the golden tests all call it. The Kernel itself sends no note-off: its output is a plain event stream in which a note is one note-on that knows the tick of its off.

**Per track.** Adjacent placements of the same clip whose phase is continuous (`next.offset == (prev.offset + prev.length) mod loopLength`, `next.start == prev.start + prev.length`) are merged into one before rendering. For each (merged) placement, loop the clip within `[start, start + length)` applying `offset`; emit enabled notes and events; channel = the Track's channel. Rendering ignores `playerId`.

**Note windows.** A note is emitted if its onset falls inside the placement window; a note whose onset precedes the window (before `offset`, or in a previous iteration) is not chased. A note plays its full length across the clip's loop boundary. Placement end truncates: note-off at `start + length`. Content at `tick ≥ loopLength` is never played.

**Equal-tick order** on one track: note-offs falling due, then non-note events in child order, then note-ons in child order. Within the non-note group nothing is reordered — an imported bank-select → program change sequence stays as imported. Where the track has AutomationLanes, its non-note events at a tick are (decided 25 Nov 2026): first the values restored at the end of a lane placement, by ascending controller number, then the events of the track's own clip in child order, then the events of each lane in lane order. A clip or lane event at the very tick of a restore therefore has the last word over the restored value. Across tracks that share a destination, tracks are processed in child order. The golden format records this order; it is not re-sorted.

**StepClip:** iterate columns in order, skip columns with the skip flag, stop at `resetAt`. Each column's `CcValue`s are emitted at the column start, on and off cells alike, before any note-on of that column. Note length = `round(gate × stepLength)` ticks, ≥ 1, in audible time. A lane with `fixedPitch` ignores cell pitches. **Consecutive on-cells in one lane with the same pitch, where the earlier gate reaches the later cell's start, merge into one note** ending where the later note would have ended (tie); a gate that doesn't reach the next cell retriggers. A note reaches the next cell when it is a step long or longer, counted in ticks after rounding, so a gate of exactly 1 ties (decided 25 Nov 2026); for a new attack on the same pitch the gate is set below 1. Consecutive means neighbours among the audible columns: a skipped column between two cells does not part them, an off cell does. The tied note begins with the earlier cell's velocity, the later cell's is not heard; its end is the later cell's also when that is earlier than the earlier cell alone would have sounded; further cells are tied on in the same way. Overlap between *different* pitches is plain overlap (legato on a monosynth). **The merge never crosses the loop point** **[D3]**: a ClipTemplate is one loop period, so the last audible column's gate runs into the next iteration as plain overlap under the note-window rule, and when the first column has the same pitch the same-pitch rule retriggers it (note-off immediately before the note-on). A lane of equal pitches with long gates therefore retriggers once per loop instead of droning. Tying across the loop point would be a renderer change (a "continues" flag on the last note, suppression of the first note-on on later iterations, offset handling), not a schema change, if it is ever wanted.

**Same-pitch overlap** on one physical destination (port, channel, pitch), any number of tracks: the pending note-off of the earlier note is emitted immediately before the new note-on, and the earlier note's original note-off is cancelled. No stuck notes, no double note-ons, ever. Export applies the same tracker, so the file never contains an overlapping same-pitch pair either. Two notes of one pitch that begin on the very same tick on one destination fall under the rule like any others (decided 25 Nov 2026): note-on, the first note's note-off, note-on, all at that tick, and the second note's length and velocity count. Note-offs that fall due at one tick are emitted in the order in which their notes began. **Without hardware** (SMF export, the golden tests) there are no ports, and a destination is a Player and a channel (decided 25 Nov 2026): two tracks that share a Player and a channel share a destination, whether or not the Player is bound, and every track without a Player is a destination of its own. Live, two Players bound to one physical port are one destination; in an export they are two. `NoteTracker` itself only numbers its destinations; who drives it says which track plays into which.

**AutomationLane merge:** a lane placement owns the set of CC numbers that occur as enabled `cc` events with `tick < loopLength` in its clip, over the whole placement, from its first tick and not from its first event. While owned, the track's clip CC events for those numbers are suppressed and the lane's events are emitted; later lanes win over earlier ones per CC, so where two lanes own a number at one tick the earlier lane's events for it are suppressed too. Everything else passes: other controllers, other kinds of event, notes. Lane placements loop their clips like any placement, and adjacent phase-continuous placements of one clip on a lane are one placement, as on a track (*Per track*): nothing happens at their seam.

At the end of a lane placement that had a CC number (no later lane owning it just then), the number goes back to whoever has it from that tick on, and the engine sends that one's underlying value (decided 25 Nov 2026):

- no lane owns it any more: the track's own chase result at that tick, i.e. the last clip CC for that number before the tick, whether it was suppressed under the lane placement or came before it; if the track's clips have sent none, nothing, and the synth keeps the lane's last value;
- an earlier lane's placement still runs and owns it: that placement's last value for the number before the tick, which was suppressed while the later lane had it; if it has sent none yet, nothing. The track's clip value stays suppressed.

A lane placement that ends underneath a later lane that has the number sends nothing. Seeking is the chase (below): seeking into an owned interval sends the lane's last value before the seek point, seeking out of one sends the underlying value. The Kernel emits the restored value as an ordinary `cc` event at the placement's end, so an SMF export holds it too. Live knob movements are sent regardless of ownership.

**Transport loop:** at `loopEnd` pending note-offs are sent, then controllers are chased for `loopStart` and playback continues there.

**Chase.** Each ClipTemplate carries, per CC number and for program change, its enabled events of that kind as a sorted (tick, value) list over one loop period. To chase a track at arrangement tick *t*, walk its placements backwards from *t*: inside a placement, "last value before phase *p*" is a binary search in the table; an earlier complete iteration contributes the table's final entry; then the previous placement, and so on. Stop at the first hit per CC. Automation ownership is consulted first — an owning lane placement answers from its own clip's table, and when leaving one the underlying value is the track's own chase result at that tick. **A seek leaves every controller as playing through from tick 0 would have** (decided 25 Nov 2026): the chased value of a CC is the last one that playback would have sent for it before *t*, a restored value included. So where the one who has the number just before *t* has sent no value yet, the answer is what the synth held when that one took the number over: a seek into a lane placement before its first event sends the value from before the placement began, and a seek to a tick after a lane placement, on a track whose clips never send that number, sends the lane's last value. For such a number the walk goes back from *t* one lane placement at a time. Cost is bounded by placements × log events, for a number that a lane has owned by the lanes' placements once more, and allocates nothing, which is why the engine may do it at a seek. The same walk serves the transport loop and automation exit; SMF export never needs it, it renders from tick 0. "Before *t*" is meant strictly: an event at *t* itself is not chased, it is played when playback goes on from *t*. Only tracks that are heard are chased, in child order, and the chased values go out at the target tick before anything that is played there. Of one track they go out in this order (decided 25 Nov 2026): bank select (CC 0, then CC 32), the program change, then the other controllers by ascending number — a synth applies a bank select only with the next program change, and loading a patch may reset its controllers, so the patch comes first and the controllers land on it. Pitch bend and pressure are not chased. The walk is `Kernel::chase`; the seek itself (pending note-offs at the tick that playback leaves, then the chase for the target) is written once, as `Renderer::seek`, and the wrap of the transport loop is that seek from `loopEnd` to `loopStart`.

**SMF export:** type 1, PPQ 960, track 0 = conductor (tempo map, time signatures, markers; each tempo written as the whole microseconds per quarter note that `TempoMap` plays **[D13]**, so the file's timing is the engine's), one SMF track per Track in track order, track-name meta event, channel from the Track, Players irrelevant. Range `[0, exportLength)` (0 = arrangement end, defined in `docs/SCHEMA.md → UiState`); notes crossing the end get their note-off at the end. Follows the document's current mute/solo, handed to the Kernel as `audibleTracks` **[D7]**. Automation lanes are merged in. No structure in meta events.

**SMF import policies:**

| case | policy |
|---|---|
| PPQ ≠ 960 | rational rescale, round to nearest tick, zero-length notes get length 1, reported |
| SMPTE time division | refused with explanation |
| type 0 | accepted, split by channel like any mixed track |
| type 2 | refused |
| mixed channels in one track | one Track per channel; channel-less SysEx goes to the lowest-numbered channel's Track, once |
| note-on velocity 0 | note-off |
| unmatched note-on / note-off | note-on without off ends at the next same-pitch on or at End-of-Track; orphan offs dropped; reported |
| overlapping same pitch | earlier note truncated at the later onset |
| End-of-Track | clip `loopLength` = EOT tick rounded up to a whole bar of the time signature at tick 0 |
| tempo / time signature / markers | merged into the Timeline from any track |
| two tempo events, or two time signatures, at one tick | the last in file order is kept, the others dropped and reported; the Timeline holds at most one per tick (`docs/SCHEMA.md`, invariant 6) |
| other meta events, SMF SysEx packets/escapes | dropped and reported |
| Players | left unassigned (rendering unaffected) |

Imported content becomes one EventClip per Track, placed at tick 0 with `length = loopLength`.

**Transform slot (later idea, none in v1).** Internal modulators such as an arpeggiator or chord player would sit as a per-track Transform between Kernel output and NoteTracker, so the Kernel's output stays a plain event stream and nothing in the document assumes otherwise; because the engine runs the Kernel per look-ahead window, a Transform there must carry its state across windows, allocate nothing, reset its state on seek, loop wrap and stop, and seed any randomness from the document so export and goldens stay deterministic; adding one means adding its header to the `engine/` row of the layer table and to `check_layers.py` on purpose; a later "freeze" command would render Kernel + Transform output back into a new EventClip, which "crop to new clip" does not do because it reads the document, not Kernel output. The Transform slot is render-side and does not cover live MIDI thru or input effects (the document never sees these; the engine has no input → output path, only input → recording).
